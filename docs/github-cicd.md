# GitHub CI/CD setup

The workflow runs only on pushes to `main`, including merges into `main`.
It runs unit tests and a production build, then deploys after validation passes.
Pushes to other branches, pull requests and manual events do not run the workflow.

## One-time setup

1. Submit the workflow changes through your branch review process.
2. Create or link the Vercel project from this checkout:

   ```sh
   npx vercel login
   npx vercel link --project vetify-anatomy
   ```

3. In Vercel, add the values from `.env.prod.example` to Production environment
   variables. This is a reference template, not an automatically loaded env file.
   Keep actual `.env.prod` files local and ignored. Keep private diagrams in a
   MongoDB GridFS database, as described in [MongoDB setup](mongodb-storage.md).
4. Generate a new session key locally:

   ```sh
   node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
   ```

   Save it as `SESSION_ENCRYPTION_KEY` in Vercel. Obtain `OIDC_ISSUER` and
   `OIDC_CLIENT_SECRET` after main implements its OIDC provider. Leaving them
   unset permits hosting the sign-in screen but does not enable shared sign-in.
5. Create a Vercel API token at <https://vercel.com/account/tokens> for the account
   or team that owns this project. Read `orgId` and `projectId` from the local,
   ignored `.vercel/project.json` generated by linking.
6. Open GitHub repository Settings, Secrets and variables, Actions. Add repository
   secrets `VERCEL_TOKEN`, `VERCEL_ORG_ID` and `VERCEL_PROJECT_ID`. App credentials
   belong in Vercel, not in the workflow, sample file or GitHub source.
7. In GitHub Settings, Environments, configure `production` to allow deployments
   from `main`. Remove any pull request requirement for this workflow's
   `Tests and production build` check because it runs only after a push to `main`.
8. Review and merge the changes into `main`. The push to `main` runs checks
   and deploys. Follow the run in Actions and find its URL in the job summary.
9. Configure `anatomy.vetify.page` using [hosting](hosting.md), then verify the
   deployed sign-in screen and anonymous picture denial.

## Checks and deployment behavior

Tests use generated PNG fixtures in a temporary directory, with no production
storage credentials. The original private diagram integrity test is explicitly
skipped when `private-assets/anatomy` is absent. Restore those files locally and
run `npm run manifest` to verify their original hashes before uploading them.
Logo integrity, all routes, authentication and mocked MongoDB storage behavior remain
covered in CI. Browser tests and real shared sign-in are separate checks.

`vercel.json` disables native Git deployments so a push cannot bypass Actions.
Production deployment uses Vercel's pull, build and prebuilt deployment flow.
The deployment job obtains production secrets from Vercel only after validation.
No generated deployment bundle or environment file is uploaded as a CI artifact.

The workflow uses Node 24 and Vercel CLI 64.5.0. Updating the CLI is an explicit
workflow change. No workflow run or cloud configuration has been performed by
adding these files locally.

References: [Vercel GitHub Actions guide](https://vercel.com/kb/guide/how-can-i-use-github-actions-with-vercel),
[GitHub Actions secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).
